# 예시: K-SAT 8 (규칙 v3.2 — 입력은 요청에서 온다)

사용자 지적의 실증: **비행소프트웨어를 아무런 정보 없이 만들 수 없다 —
정보 요청도 게시판에 올라야 하고, 그것도 산출물 요청이다. 다른 것도 전부
마찬가지다.** 이 보드에서 모든 Work의 입력은 after로 받은 산출물이거나
자기가 올린 요청의 회신이며, 도구가 이를 기계 검사한다.

- **보드**: [board/](board/) · **현황**: `python3 tools/build_board_view.py
  examples/ksat8/board` → [board.html](board.html)

## 규모 — 게시글 289건, 역할 175명, 정보 요청 56건

- GEO Ka-band 통신위성, 트랙 23개(서브시스템 13 + 서비스 5 + SE·AIT·GSE·SVC·SAT).
- **요청 56건**은 K-SAT 7(24건)의 2.3배 — "쓸 정보를 먼저 요청하라"가 만든
  차이다. **FSW는 관리하는 6개 서브시스템 전부에 TM/TC·제어 파라미터 요청을
  발행**했고, 같은 에이전트가 연기하는 OBC의 하드웨어 스펙조차 트랙이
  다르므로 게시글(REQ-FSW-OBC-HW)로 받았다.
- **입력 추적 검사 경고 0** — 289건 전 산출물의 "입력:"이 적법 경로다.
  K-SAT 3~7은 같은 검사에서 6·30·9·10·13건의 보이지 않는 종속이 나왔다.

## 검사가 실제로 잡고, 사람이 실제로 고쳤다

- **STR팀**: 회신 산출물에 부적법 인용 1건 — 도구 경고를 보고 소급 요청
  위조 대신 인용을 제거해 해소.
- **GS팀**: COMM 정정 문서를 요청 없이 인용 — **정식 요청 발행 → 회신 수령
  → 재취합**으로 해소(v3.2가 의도한 교정 경로).
- **PA 표본 감사**: 감사 항목에 입력 적법성이 추가되어 PAY 회신 2건의
  부적법 인용(상호 ICD 회신 파일의 사슬 밖 재사용)을 적발 → 수정 요청
  PAY-CORR-01/02 → PAY 종결 → 감사 재취합.
- **발행 권한 위반 적발**: GSE(경량 에이전트)가 AIT의 필요를 대신 지어내
  NEED 2건을 발행(존재하지 않는 source, take 없는 손편집) — 취합자(PM)가
  무효화했다. 규칙 위반은 등급이 낮은 에이전트에서 실제로 나온다.

## 잠정→정정 문화의 정착 (8건)

회신이 늦으면 잠정치를 명시하고 진행, 실회신이 오면 CORR/FIX 게시글로
정정: PROP 부하 2,000→3,000W, AOCS 정렬 50→21.2arcsec(마진 개선), OBC의
PAY TM 2,600→400점, HAR 어댑터 조치 등. TCS는 서비스 몫을 가로챈 실수를
착수 전에 스스로 되돌렸다.

## 발견된 새 마찰 (남은 과제로 기록)

역할 상한 검사에서 서비스 역할 4명(CM-01·PUR-01·CAL-01·FAC-01)이 7~8건으로
상한을 넘었다 — 원인은 위반이 아니라 **두 에이전트가 같은 역할 이름을 쓴
것**(일부 팀이 자기 서비스 요청을 셀프 처리). 사람 이름의 유일성이 암묵
전제였을 뿐 강제되지 않았다 — 규칙의 다음 개정 후보다.

## 끝

13개 모듈 인도 → AIT 수령 4건 + 도착 발견 3건(GSE 이행) + 통합시험 4건
PASS → 이월 3건(플랜지 CLOSED·부품 예비품 확인·Ka 시험국 계획) 처리 →
INT 재취합 → R00 마지막. 입력 추적 경고 0.
