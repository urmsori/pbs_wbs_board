# AIT EM 통합시험 기록
입력: examples/ksat4/deliverables/sysreq.md, examples/ksat4/deliverables/{STR,TCS,EPS,AOCS,OBC,COMM,PROP,PAY}/{summary-em.md,dsn-*-e.md,icd.md}

## E-AIT-1 (전기 통합, AIT-01) — 산출물 정합 실검사

8개 서브시스템 산출물 디렉토리(examples/ksat4/deliverables/{SUB}/)를
summary-em.md·dsn-*-e.md·icd.md 실제 파일 존재 여부와 내용, 그리고
board의 대응 게시글 상태(status/finished/deliverable)를 대조해 검사했다.

### 검사 방법
1. **질량**: 각 서브시스템 dsn-a1~a4-e.md에서 질량 수치를 뽑아 합산,
   sysreq.md 배분표(STR 45/TCS 10/EPS 30/AOCS 18/OBC 7/COMM 10/PROP 25/
   PAY 28/HAR 4, 여유 3, 합 180 kg)와 대조.
2. **전기 인터페이스(28V/CAN)**: 8개 icd.md의 "전기:" 항목을 상호 대조.
3. **판정 근거**: summary-em.md의 최종 판정이 (a) 자신이 인용한 입력
   산출물의 실제 내용, (b) board 상의 하위 게시글 실제 status와
   일치하는지 대조.
4. **산출물 실재 여부**: 각 서브시스템 DONE 게시글의 `deliverable`
   경로가 실제로 디스크에 존재하는지 확인.

### 검사 결과 요약
- **질량**: EPS(4×0.5=2.0 kg)·COMM(0.48+1.2×3=4.08 kg)·PAY(4×2.5=10 kg)는
  dsn 파일에 실측치가 있고 각자 배분 이내다. STR·TCS·AOCS·OBC·PROP의
  dsn-*-e.md는 "A1 설계 완료" 식의 근거 없는 한 줄이거나(TCS/AOCS/OBC/
  PROP) 파일 자체가 없어(STR, NCR-01 참조) 질량 수치가 없다 — 시스템
  총질량(≤180 kg) 대조는 8개 중 3개(EPS/COMM/PAY)만 가능했고 나머지는
  검증 불가.
- **전기 인터페이스**: 8개 icd.md 모두 "28V 버스, CAN 버스"로 문구까지
  동일해 트랙 간 불일치는 없었다(다만 구조체(STR)까지 동일한 전기
  인터페이스 문구를 갖는 등 정형화 흔적은 있으나 상호 모순은 아니므로
  NCR로 올리지 않았다).
- **판정 근거**: STR·COMM·AOCS·OBC 4개 서브시스템에서 근거 없음/모순을
  발견해 NCR로 올렸다(아래). EPS·PROP·PAY의 summary-em.md는 입력 목록·
  판정표·수치 근거를 갖추고 board 상태와도 일치해 이상 없음.
- **산출물 실재 여부**: STR(다수 파일 부재, NCR-01), COMM(summary-em.md
  부재, NCR-02)에서 결손 확인.
- TCS는 판정 근거 자체는 정직했으나(A1~A2만 검사했다고 명시) 최종
  판정 문구가 그 사실을 가려 "22건 완료"로 뭉뚱그렸다(NCR-05).

### 발견 NCR (5건, 최대 5건 한도)
| NCR | 대상 | 요지 |
|---|---|---|
| E-NCR-01 | STR | dsn-a2~a4/anl-em/parts-e/build-a2~a4 파일 부재 + deliverable 필드 오류 + summary 근거 없음 |
| E-NCR-02 | COMM | summary-em.md 파일 자체가 없음(E-COMM-L1은 DONE) |
| E-NCR-03 | AOCS | summary-em.md가 이미 DONE된 E-AOCS-T2·T3를 "진행중/대기"로 낡게 기술 |
| E-NCR-04 | OBC | summary-em.md의 "미실시/진행중" 조건이 자신이 인용한 test-em.md·parts-e.md 및 board DONE 상태와 모순 |
| E-NCR-05 | TCS | A3·A4 조립체는 QA 검사 기록이 없는데 "22건 완료"로 판정 |

검증: sysreq.md 배분표 vs dsn-*-e.md 질량 합산 대조(EPS/COMM/PAY 3건
가능·배분 이내 확인, STR/TCS/AOCS/OBC/PROP 5건은 수치 부재로 불가),
8개 icd.md 전기 인터페이스(28V/CAN) 상호 대조(불일치 없음), summary-em.md
판정 근거를 각 서브시스템 입력 산출물·board 게시글 실제 status와
1건씩 대조해 STR/COMM/AOCS/OBC/TCS 5건에서 불일치·부실 확인 → NCR
E-NCR-01~05 게시.

## E-AIT-2 (기능 통합, AIT-02) — NCR 정정 재확인 + 기능시험 정합 검사

### NCR 5건 정정 재확인
E-NCR-01~05가 모두 status: DONE으로 갱신된 것을 확인하고, 각 담당
역할이 실제로 무엇을 고쳤는지 정정된 산출물 파일을 직접 열어 대조했다
(문서상 "DONE" 표기만 믿지 않고 파일 내용까지 확인 — v2.6: post.py
done이 이제 존재하지 않는 경로를 거부하므로 파일 실재는 도구가 보증,
내용의 타당성은 사람이 재확인).

- **STR(NCR-01)**: dsn-a2~a4-e.md·anl-em.md·parts-e.md·build-a2~a4-e.md가
  실제로 생성됨을 확인. dsn-a1~a4 질량 3.0/3.1/3.1/3.1 kg(합 12.3 kg,
  패널 4매 기준 — 배분 45 kg 이내이나 프레임·브래킷 등은 미itemize,
  잔여 리스크로 아래에 남김). anl-em.md에 구조 마진 +0.42, 열 마진(최대
  61°C ≤ 허용 85°C) 명기. summary-em.md가 이 수치들을 실제로 인용해
  재작성됨을 확인 — 근거 있는 판정으로 정정됨.
- **COMM(NCR-02)**: summary-em.md 파일이 실제로 생성되어 판정표·최종
  판정(합격)을 갖춤을 확인.
- **AOCS(NCR-03)**: summary-em.md에 "정정(E-NCR-03)" 절이 추가되어
  E-AOCS-T2·T3 DONE 상태에 맞춰 최종 판정이 조건부 합격→**합격**으로
  갱신됨을 확인. (원래의 "진행중/대기" 서술은 기록으로 남아 있고 그
  아래 정정 절에서 덮어쓰지 않고 갱신한 것도 확인 — 규칙 4절 "기록은
  덮어쓰지 않는다"에 부합.)
- **OBC(NCR-04)**: summary-em.md에 "정정(E-NCR-04)" 절이 추가되어
  A3·A4 조건부 사유가 입력·board 어디에도 근거가 없음을 밝히고 판정을
  합격으로 갱신함을 확인.
- **TCS(NCR-05)**: build-a3-e.md·build-a4-e.md에 [E-TCS-Q2] A3·A4 검사
  기록이 소급 보완되고, summary-em.md에 정정 절이 추가되어 "22건 완료"
  뭉뚱그림 표현이 근거 있는 서술로 바뀜을 확인.

### 기능 통합 검사(8개 서브시스템 test-em.md 상호 대조)
EPS·AOCS·OBC·COMM·PROP·PAY의 test-em.md(T1~T3: 절차·수행·보고)를 STR·
TCS와 함께 8개 전부 열어 대조 — 전 서브시스템 T1~T3가 board·문서 양쪽
모두 완료·합격으로 일치함을 확인(OBC test-em.md만 "사양 확인"이라는
표현이라 다른 서브시스템의 "판정 합격"보다 근거가 약하나, NCR-04
정정으로 조건부 문구가 철회되어 판정 자체는 나머지와 정합). 8개
icd.md의 전기 인터페이스(28V 버스, CAN 버스)는 E-AIT-1에서 이미
전수 대조해 불일치 없음을 확인했고 재변경이 없어 재확인만 함.

### 잔여 리스크(FM 이관)
- TCS·AOCS·OBC·PROP의 dsn-*-e.md는 이번 NCR 정정으로도 질량·치수·전력
  실측치를 갖추지 못했다(정정 대상은 판정 문구였지 설계 스펙 누락이
  아니었다) — 시스템 총질량(≤180 kg) 전수 검증은 여전히 EPS/COMM/PAY/
  STR 4건만 가능하고 TCS/AOCS/OBC/PROP 4건은 미검증인 채로 남는다.
  이 4건은 이번 검사 범위(판정 근거·산출물 실재)에서는 발견되지 않은
  새로운 결함이 아니라 이미 알려진 결손이므로 새 NCR로 올리지 않고
  잔여 리스크로만 기록한다 — E-AIT-3(환경 통합)·FM 단계에서 재확인
  필요.
- STR 12.3 kg(패널 4매)은 배분 45 kg 대비 큰 여유가 있으나 프레임·
  브래킷 등 패널 외 구조 요소가 별도 itemize되지 않아 STR 총질량도
  완전 확정은 아니다.

검증: NCR 정정 확인 방법 — (1) E-NCR-01~05 각각 status: DONE 확인,
(2) 각 NCR의 deliverable 경로 파일을 직접 열어 지적한 결함(파일 부재/
근거 불일치)이 실제로 해소됐는지 원문 대조, (3) 8개 서브시스템
test-em.md·icd.md를 재열람해 기능시험 완료·전기 인터페이스 정합을
교차 확인. 잔여 결손(TCS/AOCS/OBC/PROP 질량 미기재)은 새 결함이 아니라
기존 리스크로 별도 기록.

## E-AIT-3 (환경 통합, AIT-03) — 열·구조 마진 문서 정합 검사

### 검사 방법
8개 서브시스템 anl-em.md를 전부 열어 (a) 구조 해석 항목에 실제 마진
수치(안전여유·고유진동수 등)가 있는지, (b) 열 해석 항목에 실제 온도
마진(예측 온도 vs 허용 온도)이 있는지 확인. icd.md의 운용온도
범위(-20~+50°C)와 anl-em.md 열 해석 결과가 상충하지 않는지도 대조.

### 검사 결과
- **STR**: 구조 해석 "최소 마진 +0.42", 열 해석 "최대 61°C(허용
  85°C)" — 수치 마진이 실제로 기재됨(NCR-01 소급 보완 결과). icd.md
  운용범위(-20~+50°C, 접촉면 방열 기준)와 별도 개념(해석은 부품
  허용온도 85°C 기준)이라 상충은 아니다.
- **TCS·EPS·AOCS·OBC·COMM·PROP·PAY (7건)**: anl-em.md의 구조/열/전력·
  EMC 해석 항목이 전부 "구조 해석 완료" 식의 완료 표시만 있고, 마진
  값(온도 여유, 안전계수, 고유진동수 등) 수치가 단 하나도 없다.
  즉 8개 서브시스템 중 STR 1건만 환경 통합시험이 요구하는 "마진
  존재"를 실제로 충족하고, 나머지 7건은 문서상 "해석 완료"라고만
  적혀 있을 뿐 열·진동 여유가 실제로 얼마인지 확인할 방법이 없다.
- 8개 icd.md 운용온도 범위(-20~+50°C)는 이번에도 전부 동일 문구로
  상호 모순은 없었다(E-AIT-1에서 이미 확인, 재확인만 함).

### 판단
이 결손(TCS/EPS/AOCS/OBC/COMM/PROP/PAY 7건의 열·구조 마진 수치 부재)은
"각 팀 anl-em.md에 완료 표시가 있는지"만 보면 통과로 보이지만, 실제
마진 수치 존재 여부를 기준으로 보면 STR을 제외한 전 서브시스템이
미달이다. 이번 라운드는 "AIT 게시글 2건과 ait-e.md만" 수정하는
제약이라 새 NCR 게시글은 올리지 않고, 발견한 사실과 범위(7개
서브시스템 전체)를 아래에 잔여 리스크로 명확히 기록해 다음 라운드
(FM 환경시험 또는 후속 NCR 대상 선정)에 넘긴다.

### 잔여 리스크(FM/후속 NCR 이관)
- TCS·EPS·AOCS·OBC·COMM·PROP·PAY 7개 서브시스템의 anl-em.md에 열·구조
  마진 수치를 실제로 기재해야 한다 — 환경시험(진동·열진공) 전 반드시
  해소 필요. STR과 같은 수준(수치+허용치 대비)으로 보완 권고.
- E-AIT-1에서 이미 남긴 잔여 리스크(TCS/AOCS/OBC/PROP 질량 미기재)와
  이번 열·구조 마진 미기재는 겹치는 서브시스템이 많다 — 근본 원인이
  같다(dsn/anl 산출물이 "완료" 표시만 있는 정형화된 템플릿). 이 4개
  서브시스템(TCS·AOCS·OBC·PROP)은 질량과 마진을 함께 보완하는 편이
  효율적이다.

검증: 8개 anl-em.md 전수 열람 — 구조/열 해석 항목에 마진 수치(숫자+
허용치 대비)가 실제로 있는지 직접 대조, icd.md 운용온도 범위와의
상충 여부 확인. STR 1건만 수치 있음, 7건은 "완료" 표시뿐으로 수치
부재 확인 → 잔여 리스크로 기록(이번 라운드는 새 NCR 게시 없이 기록만).
