# 예시: K-SAT 4 지구관측위성 (조직 308명, 규칙 v2.4·v2.5)

PBS WBS Board 규칙의 **사람(역할) 단위** 검증 예시다. K-SAT 3(20건)이 "발견되는
보드"를 보였다면, 이 보드는 실제 조직 규모를 보인다: **Work의 단위 = 사람
1명의 인수인계 패키지**, 에이전트 1명이 사람 여러 명의 역할을 나눠 맡는다.

- **보드**: [board/](board/) — 킥오프 발행 418건 + 진행 중 발견(NCR 등).
- **현황**: `python3 tools/build_board_view.py examples/ksat4/board` →
  [board.html](board.html). **Gantt가 기본 화면**이고 모듈별/사람별/계층
  모드로 전환한다(규칙 v2.5) — 사람별 모드에서 역할 300여 명의 레인이 보인다.

## 조직 (308명 — owner에 이 이름들이 기록된다)

| 조직 | 인원 | 역할 예 |
|---|---|---|
| 시스템엔지니어링 SE | 10 | SE-01(요구·판정), SE-02~09(ICD), SE-10(WP 발행) |
| 서브시스템 8팀 | 8×24=192 | {SUB}-DSN-01~04, ANL-01~03, PRC-01~02, MFG-01~05, QA-01~02, ASM-01~03, TST-01~03, LEAD-01, DOC-01 |
| 조립·통합·시험 AIT | 25 | AIT-01~25 (통합시험 — NCR 발견의 주체) |
| 시험시설 FAC | 12 | 진동·열진공 슬롯 운용(공용 자원 게이트) |
| 비행SW / 지상국 / 하니스 | 20/15/10 | SW-*, GS-*, HAR-* |
| 발사체연계 / 품질보증 / 사업관리 | 8/10/6 | LV-*, PA-*(표본 감사), PM-* |

## 에이전트 ↔ 역할 배정 (1:N)

haiku-{sub}: 서브시스템 팀 22명 역할 · haiku-sup: 지원 조직 ~40명 역할 ·
sonnet-ait: AIT(정합 실검사·NCR 게시) · claude: SE 판정 역할.
보드에는 에이전트가 아니라 **사람(역할) 이름만** 남는다 — 사람별 Gantt
레인이 그 증거다.

## 체인 (인수인계가 곧 게시글)

설계(DSN) → 해석(ANL)·구매(PRC) → 제작(MFG) → 검사(QA) → 조립(ASM) →
시험(TST, **공용 시설 슬롯 FAC를 after로 대기**) → 팀 취합(LEAD) →
AIT 통합(정합 실검사 → 불일치는 NCR 게시글로) → SE 판정 → FM 반복 → FRR.

## 결과 (루트 K4 취합)

- 게시글 427건(킥오프 418 + 발견 NCR 9) 전부 DONE — FRR "FM 인도 가능".
- 사람(역할) 308명이 owner로 기록됨. 에이전트 21회 투입(haiku 18, sonnet 2,
  claude): 에이전트당 역할 평균 15명분.
- 재작업 기록: EM NCR 5건(없는 파일 DONE·부실 판정 등), FM NCR 4건(설계
  수치 미기재) — 전부 AIT의 실검사 발견 → 역할별 정정 → 재확인.
- 이 보드에서 규칙 v2.6(산출물 파일 존재 검사)이 태어났다.
