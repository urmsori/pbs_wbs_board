# 예시: 결혼이라는 프로젝트 (부부 관점 전체 여정, v3.3)

본식 하루(examples/wedding)가 아니라 **상견례부터 결혼 이후 정리까지** —
필요의 주인인 부부(지우·민준)가 단계를 스스로 발행하고, 홀·스드메·부동산·
은행·여행사·청첩·가전·양가·구청·스튜디오는 전부 부부의 요청을 받는
상대방이다.

- **여정 뷰(폰 우선, Gantt 없음)**: `python3 tools/build_journey_view.py
  examples/journey/board` → [journey.html](journey.html)
- 보드: [board/](board/) · Gantt 뷰도 같은 자료로 여전히 가능: [board.html](board.html)

## 여정 (46건 · PH1~PH6)

PH1 시작(상견례·날짜·예산 배분) → PH2 큰 계약(홀·스드메·신혼집·대출) →
PH3 채우기(예물·여행·가전·청첩 시안) → PH4 알리기(촬영·발송·모임·가봉) →
PH5 본식(인원·이사·준비 완료 확인 — 본식 상세는 examples/wedding 보드,
부부는 그 런시트를 읽고 서명) → PH6 이후(혼인신고·전입·축의금 정산·감사
인사·여행 정산·앨범·양가 첫 방문) → 루트(여정 완료)가 마지막.

## 규칙이 확인된 장면들

- **모르는 것은 전부 요청으로**(v3.2): 요청 13건 — 상견례 형식은 양가에,
  홀 시세는 홀에, 대출 한도는 은행에 물었다. **은행 회신이 늦어 4.5억 전액
  대출 가정으로 잠정 계약 → 정식 승인 3.7억 도착 → CORR 게시글로 자기자금
  계획 정정** — 잠정→정정 경로가 부부의 여정에서도 그대로 돌았다.
- **단계당 역할 상한**(v3.3): 부부 둘이 46건을 가면 총량 상한(6건)은
  구조적으로 깨진다 — 단계당 상한으로 정교화된 규칙 아래 실측 최대 4건/단계.
- **100만 원 원칙**: 큰 결정 산출물은 전부 공동 서명(BRIEF의 5원칙).
- **예산 결산**: 5,500만 예산 → 실지출 4,788만(712만 절감), 신혼집 별도.
- 입력 추적 경고 0, 루트 마지막.

## 뷰에 대하여 (v3.3 — 뷰는 하나가 아니다)

이 보드의 기본 뷰는 Gantt가 아니라 **여정 뷰**다: 진행 링, "지금 할 일",
단계별 접이식 카드, 카드 탭 → 왜 사슬·남긴 기록 바텀시트. 자료는 Gantt
뷰와 같은 한 벌이고 검사도 같은 것이 돈다 — 뷰만 이용자(폰을 든 부부)에
맞게 골랐다.
