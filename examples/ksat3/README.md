# 예시: K-SAT 3 기술검증 큐브샛 (규칙 v2.3의 모범 사례)

PBS WBS Board 규칙(../../RULES.md) v2.3 — "게시글은 인수인계 경계에만,
필요는 발견되는 대로, 재작업은 정상" — 을 실제로 돌려 검증한 예시다.
K-SAT 2(../satellite-full/, 반례)와 정반대의 진행 방식이다.

- **보드**: [board/](board/) — 시작은 7건, 끝은 진행하며 발견된 필요만큼.
- **현황**: `python3 tools/build_board_view.py examples/ksat3/board` →
  [board.html](board.html)

## 이 예시가 보여주는 것

1. **게시글 = 남이 해줘야 하는 필요.** 트랙 Work(K10/K20/K30)는 각각
   하나다 — 설계·해석·시제 같은 내부 단계는 게시글이 아니라 본문의 "작업
   기록"에 줄로 쌓인다. 게시글로 올라온 것은 전부 다른 트랙이 해줘야 하는
   것들(K51~K72 교차 요청, K81~K84 수정 요청)이다.
2. **필요는 발견된다.** 선게시는 확실한 7건뿐. 나머지 10건은 에이전트들이
   일하다가 올렸다. 산출물 md는 전부 머리에 "입력:"으로 외부 종속을
   밝힌다 — 입력 없는 산출물은 루트 요구(sysreq.md) 하나뿐이다.
3. **재작업이 기록에 남는다.**
   - EPS가 K71에서 자기 기준선(1S 비조절 버스)으로는 COMM의 12W 버스트 시
     ≥7.0V가 **구조적으로 불가**함을 정직하게 판정 → K20 안에서 Rev.A→Rev.B
     (2S2P+부스트) 재설계. eps-em.md에 개정 이력이 쌓인다.
   - 통합시험(K40) 1차에서 **불합격 3건** 발견: 낡은 교차 시트(eps-to-str가
     Rev.A 수치), COMM 질량 추산 누락, STR 자체 문서 간 개구부 모순
     (90mm=수납 포락선 vs 30mm=관통 개구부). 수정 요청 K81~K84 → 수정 →
     재시험. 같은 파일(eps-to-str.md, comm-em.md, str-em.md)이 여러 Work로
     거듭 갱신되었다.
4. **정직한 미결.** EM 단계에서 못 닫는 항목(부품 미선정, 하드웨어 미검증)은
   지우지 않고 "FM 이관"으로 남는다 — FM 필요는 EM 판정 후에야 게시된다.

에이전트: sonnet-str / sonnet-eps / sonnet-comm (트랙, 웨이브마다 같은
에이전트가 이어서), sonnet-ait (통합시험), claude (루트·요구·취합).
