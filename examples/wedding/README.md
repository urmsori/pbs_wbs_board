# 예시: 웨딩 런시트 (규칙 일반성 검증 — 위성이 아닌 도메인)

**런시트는 혼자 만들 수 없다.** 사회자·축가·피아니스트·사진·영상·메이크업·
플로리스트·식장 매니저·음향·조명·연회·안내·버스·양가 가족 — 이 보드의
런시트 모든 줄은 그들 중 누군가의 인도 산출물이거나 요청의 회신이다(v3.2).

- **보드**: [board/](board/) · **런시트**: [deliverables/PLAN/runsheet.md](deliverables/PLAN/runsheet.md)

## 규칙이 그대로 옮겨진 장면들

- **플래너는 결과 요청만**(v2.7): 시작 게시글은 파트 계획 인도 요청 11건 +
  신랑신부 BRIEF + 리허설 + 루트뿐. 분해는 각 파트의 주인이 스스로 했다.
- **정보 요청 전면화**(v3.2): 사회자는 성혼선언 낭독자를, 축가팀은 마이크
  수·MR 포맷을, 사진팀은 원판 장소를, 메이크업은 시안을 — 전부 게시글로
  요청했다(요청 20여 건, 신랑신부·양가가 9건 회신).
- **직능 다양성**(v3.1): 사람(역할) 34명 — 음향감독과 조명감독이 다르고,
  듀엣 두 사람과 피아니스트가 다르고, 축의대 4명은 이름까지 정해졌다.
- **리허설 = 도착 시 발견**(v2.7): 워킹 실측 55초 → 입장곡 루프 확정, 화동
  6세 중간 멈춤 → 이모 동반 방식, 신랑 입장곡 미정 발견 → 현장 확정,
  소회의실 배정·반입 병목 → 시간 분리. 발견 4건 전부 게시글 왕복(source=REH).
- **정직·자기 적발**: 스타일팀이 남의 회신을 몰래 재사용하다 스스로 발견해
  정식 요청으로 교체했고, MC가 이미 종료돼 회신이 안 오자 "잠정·자체 추정"
  을 명시하고 진행했다(뒤에 실회신으로 갱신).
- **취합은 마지막**(v1.2): 리허설 발견이 모두 닫힌 뒤에야 런시트가 취합됐고,
  루트가 시간상 맨 마지막이다. 입력 추적 경고 0.
